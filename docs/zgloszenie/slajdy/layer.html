SIMON adds no measurable cost

We sent the same jobs to vLLM directly and through a SIMON node. The client verified every receipt.

Qwen3.8-27B BF16, vLLM 0.27.1, 256 tokens per job. One job takes about 14 ms more. The client ran on the same host, so the WAN is not in these numbers.

Until 12 October a SIMON node ran one prompt at a time, and it lost some parallel prompts. Now the node runs jobs concurrently, with a limit and an explicit busy error. At 16 and 64 streams the SIMON rows are a little higher. We do not claim a speed-up: each job is a separate agent process, so the requests arrive spread out, and the direct client sends them in waves. Read it as no measurable overhead.
